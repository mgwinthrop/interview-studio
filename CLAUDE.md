# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Interview Studio: a voice-conversation tool where an AI interviewer asks questions and then produces a transcript and a written reflection. Two independent npm projects (no workspace root install): `apps/backend` (Node/Express/WebSocket/Prisma+SQLite) and `apps/frontend` (Next.js 14 App Router). Single-user prototype: local mode (no `AUTH_TOKEN`) accepts loopback peers only, with `Host` and `Origin` checks; setting `AUTH_TOKEN` enables an optional shared-token mode. Read `AGENTS.md` for the binding repo rules (never commit credentials, transcripts, databases or deployment identifiers; keep changes inside this repo).

## Commands

Requires Node 20+. Install per app: `npm --prefix apps/backend ci` and `npm --prefix apps/frontend ci`. Copy `apps/backend/.env.example` to `.env` and `apps/frontend/.env.example` to `.env.local`.

Backend (`apps/backend`):
- `npx prisma generate` — required once after install, and after schema changes
- Upgrading an existing database (migrations run at startup, `prisma generate` does not): see "Upgrading an existing install" in `docs/local-setup.md`
- `npm run dev` — tsx watch on `127.0.0.1:3001`. With the default `PROFILE=cloud` it needs `ANTHROPIC_API_KEY` and `ELEVENLABS_API_KEY`; `PROFILE=mock npm run dev` runs a full conversation (greeting, replies, interrupt, report) with no keys
- `npm test` — vitest unit tests plus the keyless end-to-end conversation test (`src/__tests__/conversation.test.ts`, mock providers, temp SQLite DB; no keys or running server) (also `npm test` at repo root); single file: `npx vitest run src/__tests__/orchestrator.test.ts`; single test: `npx vitest run -t "name"`
- `npm run test:integration` — opt-in run of a real session against real providers over WebSocket with an LLM judge. Needs the backend already running with `PROFILE=cloud` and real API keys (also `ANTHROPIC_API_KEY` in the test's environment for the judge); sets `INTEGRATION_TEST=1`; `TEST_WS_URL` overrides the default `ws://localhost:3001`. Excluded from `npm test`.
- `npm run build` — `tsc`

Frontend (`apps/frontend`): `npm run dev` (port 3000), `npm run lint`, `npm run build`. There are no frontend tests.

Before publishing, run all of: `npm test`, frontend lint, frontend build, backend build.

`http://localhost:3000/avatar` previews every avatar state with no backend, keys or microphone. Use it to check UI states and reduced motion.

## Architecture

Pipeline: browser mic → AudioWorklet (PCM16, 16kHz mono) → Silero VAD (`@ricky0123/vad-web`, client-side, decides end of turn) → WebSocket binary frame (one whole utterance) → STT (one request per utterance, not streaming) → LLM → `sentenceChunker.ts` → TTS → binary MP3 frames back → `lib/audioQueue.ts` (Web Audio, serialised playback). `docs/architecture.md` has the latency budget and diagram.

Backend:
- `index.ts` — thin entrypoint: `loadConfig` (`config.ts`; exits on a bad setting), `runMigrations` (`migrate.ts`; exits on failure), `createProviders`, `createApp`, `listen`.
- `app.ts` — `createApp` builds the Express routes and the single WebSocket endpoint at the root path without listening (tests use it on port 0). `auth.ts` runs on every HTTP request and on the upgrade (origin check, loopback-only local mode, optional `AUTH_TOKEN`) and yields the `ownerId` every query filters by. The server issues session IDs; binary frames (`isBinary`) are audio, everything else is typed JSON, and `session_start` must be the first frame and names an `interviewerId` or carries a `draft`.
- `providers/` — STT, LLM and TTS interfaces with cloud (ElevenLabs Scribe, Claude, ElevenLabs TTS with optional Cartesia fallback) and mock implementations; `PROFILE=mock` needs no keys.
- `sessionController.ts` — one controller per connection: turn queue, interrupt and abort flow, idle timeout, end and report; `sessionRegistry.ts` tracks live controllers. `orchestrator.ts` holds the pure turn helpers, including `advancePhase`. Phase transitions are driven by per-phase user-turn counts from the interviewer's own settings, never decided by the LLM.
- Interviewers (see `docs/architecture.md`, "Interviewers"): `interviewer/schema.ts` defines the record, its caps and validation; `interviewer/presets/` holds the four preset interviewers (`tell-a-story`, `explain-an-idea`, `rehearse-an-interview`, `work-out-a-point-of-view`) as repo files, plus the hidden designer preset (`designer.ts`, `interviewer-designer`; not listed by `GET /api/interviewers`, synced with the others through `SYNCED_PRESETS`); `interviewer/prompt.ts` builds the system prompt (fixed voice-rules wrapper around the interviewer's text); `interviewerStore.ts` is the owner-scoped store over the `Interviewer` table (50 custom interviewers per owner, versioned updates, `syncPresets`); `interviewerRoutes.ts` serves `/api/interviewers`. `index.ts` syncs the presets into the database after migrations. A session stores a full snapshot of its interviewer (`Session.interviewerJson`), so editing or deleting an interviewer never changes a past or running session or its report; sessions from before interviewers have no snapshot and show as "Earlier interview".
- `persistence.ts` + `prisma/schema.prisma` write to SQLite as turns complete, on phase changes and when the session ends (`complete`, `failed` or `abandoned`). `reportGenerator.ts` builds the post-session report.
- Delivery metrics: `delivery/metrics.ts` computes per-turn numbers (pace, pauses, filler count, answer length, response gap) from the STT word timings in code, and `summarizeDelivery` rolls them up. `sessionController.ts` stores them as numbers only in `ConversationTurn.metricsJson` for audio turns (text input has none). The client measures the response gap and sends it as `turn_timing` just before the audio frame (`noteResponseGap`).
- Report v2: `reportGenerator.ts` makes one structured LLM call (`REPORT_MAX_TOKENS` 3072, a deliberate exception to the 300-token conversational limit) and returns `ReportV2` (`format: 2`: Content, Delivery, Next steps). The interviewer's `contentFeedback` and `deliveryFeedback` switches choose which parts are asked for; the delivery numbers are put in by code, and the model only writes a plain-language `reading`, which `delivery/readingCheck.ts` drops (with a fixed log line) if it quotes a number outside the summary. `Report.reportJson` holds the `ReportV2` and the legacy report columns are still filled; a row without `reportJson` is served as `format: 1`. `REPORT_FILLER_COUNTS=1` (or `true`) shows filler counts in reports; they are stored either way (see "Delivery metrics and the report" in `docs/architecture.md`).
- Designer and ephemeral sessions (see "Creating an interviewer" in `docs/architecture.md`): the hidden preset `interviewer-designer` (`interviewer/presets/designer.ts`) talks through an interviewer and, on `session_end`, `generateDraft` (`interviewer/designer.ts`) turns the conversation into a validated draft sent as a `draft` message; a `session_start` with an inline `draft` runs it as a trial ("Try it"). Both are controller kinds (`designer`, `trial`) wired in `app.ts` to `EPHEMERAL_PERSIST` (`ephemeralPersist.ts`) and share the stored session's start path, caps and cleanup. `POST /api/interviewers/draft` makes a draft from one description over HTTP.
- Regenerate: `POST /api/session/:sessionId/report/regenerate` rewrites the report of a `failed` session synchronously (same deadline as session end) and moves it to `complete` through `completeFailedSession` in `persistence.ts`.
- Data lifecycle: `DELETE /api/session/:sessionId` (owner-scoped; 204, 404 for unknown or foreign, 409 while the session is live) removes a session with its turns and report; the dashboard has a delete button. Set `RETENTION_DAYS` to have `retention.ts` purge ended sessions older than that once at startup (a failure is logged and does not block startup).

Frontend: `app/session/page.tsx` is the live conversation, built on `hooks/useWebSocket.ts`, `hooks/useVAD.ts` and `lib/audioQueue.ts`. `app/components/InterviewerAvatar.tsx` is an inline SVG animated by CSS in `globals.css`. `app/lib/interviewers.ts` loads interviewers from the API (the frontend hard-codes no interviewer ids except the hidden designer's, `DESIGNER_ID`); the session page loads the interviewer before it opens the WebSocket. The session page also takes `mode=design` (a designer session; the `draft` goes to the editor) and `mode=try` (Try it on the stored draft, then back to the editor); neither shows a report (the designer's id implies `mode=design`). Talk it through and Try it open the session through `startVoiceSession` (`app/lib/voiceSession.ts`): straight there when the mic check has just passed, otherwise via `/mic-check?next=<path>`, which honours only same-site `/session?` paths. `app/interviewers/page.tsx` lists the interviewers and offers the three ways to create one (talk it through, describe it, blank form) plus duplicate and delete; `app/interviewers/edit/` is the editor (`?id=` to edit or view a preset read-only, `?from=design|draft` for a stored draft, nothing for a blank form) with Save, Try it, Duplicate and Delete. `app/lib/interviewerForm.ts` holds the form model, a copy of the backend's `INTERVIEWER_LIMITS`, and the `sessionStorage` draft hand-off (`interviewer_draft`, shape-checked on read; a corrupt value opens a blank form). Report and history pages are `app/report/[sessionId]` and `app/dashboard`. The three-part report is rendered by `app/components/ReportView.tsx` (types and parser in `app/lib/report.ts`), and the report page has a regenerate button for failed reports.

## Contracts to keep stable

- The WebSocket protocol is specified in `docs/websocket-protocol.md`. Keep client, server and that doc in sync. Do not change the audio framing or message types unless the task says to.
- `turn_timing` (`{ type, responseGapMs }`, client to server) is optional, attaches only to the next audio frame, is never applied to text input, and is ignored unless it is a finite number from 0 to 600000. Its shape is in `docs/websocket-protocol.md`.
- Audio is never stored. Per turn only the delivery numbers are kept (no audio, no word list), and text-input turns have none.
- Delivery numbers shown in a report come from code, never from model output. The model's `reading` is interpretation only: numbers in a reading must come from the summary; otherwise the reading is omitted (`delivery/readingCheck.ts`; the report still completes, so `delivery.reading` is optional).
- Old reports keep loading: a report row without `reportJson` is `format: 1` and renders as before, and the legacy report columns stay filled.
- A session leaves `active` exactly once. The only other transition is `failed` to `complete`, done by `completeFailedSession` for regenerate.
- `session_start` carries `interviewerId` xor `draft` (anything else closes 1008). Designer and trial sessions are ephemeral and never write to the database (no `persistSessionCreate`, only `EPHEMERAL_PERSIST`). A draft is never saved except by the client through `POST`/`PUT /api/interviewers`.
- Interrupts must stop both audio playback (`audioQueue.flush()`, which bumps a generation counter to discard in-flight decodes) and the server's TTS and LLM streams (one abort signal per turn) and drop queued utterances. The client snaps to the interrupt state locally before any server round-trip.
- Avatar states must reflect real connection, pause, interrupt and audio-playback state, not timers, and must respect `prefers-reduced-motion`.
- `docs/architecture.md` lists "locked decisions" (Claude Sonnet model with `max_tokens: 300` for conversation replies (the report call has its own budget of 3072), Scribe v2, `eleven_flash_v2_5`, 16kHz PCM16). Treat them as fixed unless explicitly asked to change them. Phase thresholds are not locked: they are per-interviewer settings. The presets default to 2/5/10 cumulative user turns (intro 2, share 3 more, deep dive 5 more), and demo mode ends each phase at its `minTurns`.
