**Interrupted interviewer replies (the done_when clause).** What is stored depends on
whether the server had finished the reply when the interrupt arrived:
- **Interrupted while the server is still generating or speaking** (from code; the verifier
  agrees): nothing is stored. `respond()` returns at `if (ctx.interrupted) return;`
  (`sessionController.ts:428`), before `addTurn("assistant", …)` (`:434`), so not even
  sentences already spoken are kept. The two user answers are then adjacent.
  `questionFor` returns null for the later one, so its card shows no "Q:" line, never a
  wrong question. `conversation.test.ts:235-236` already asserts that the interrupted reply
  is not stored. This cannot be reproduced on the mock profile, because mock replies finish
  instantly.
- **Interrupted after the server finished, while the browser is still playing the reply**
  (observed on a real mock session; a scratch spec, deleted, not committed):
  - Frames: `session_start, turn_timing, audio, turn_timing, audio, interrupt, audio`.
  - Stored: `assistant, user 1, assistant, user 2, assistant, user 3, assistant`.
  - The reply that was cut off client-side was stored in full, because the server had
    already completed and stored it before the `interrupt` arrived.
  - `questionFor` shows the whole reply as the next answer's question, including any part
    the person did not hear. That is more than was heard, never a wrong question.
- With real TTS, which streams for seconds, the first case is probably the common one.
