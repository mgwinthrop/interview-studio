in `files_expected`, none load-bearing, no existing test modified.

Test first, and a finding about the mock: the first version of
`e2e/transcript-opacity.spec.ts` sampled opacity on every animation frame while the panel read
"Speaking" and recorded zero samples. A probe showed why: the mock backend sends `tts_start`
and `tts_end` about 8 ms apart (mock TTS has no delay by default; `ttsDelayMs` is only
settable from code in `providers/`, which is load-bearing) and the page plays no audible audio
in the test, so the panel goes straight to "Listening". The spec now uses
`page.routeWebSocket` to pass through to the real mock backend while holding back the first
`tts_end`; that keeps "Speaking" up for the checks. No app or backend change. Without the fix
it failed on `Expected: 1, Received: 0.4`.
