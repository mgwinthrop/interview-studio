# Settings Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner choose, from a Settings page, the Claude model for each job, the reply length, the speech models and the spoken-reply format, and enter Claude prices, with live model lists and recommended defaults that are picked once and remembered.

**Architecture:** A pure settings module (types, defaults, validation) and a small Prisma store hold per-owner values and prices. A model catalog fetches and caches Anthropic's and ElevenLabs' live lists and derives tiers and recommendations. A settings service combines them (resolve-and-remember defaults, validated saves, reset). Providers take the model, speech model and output format per call instead of constants; sessions snapshot settings at start; reports and drafts read them when they run; usage prices come from the database. A new `/settings` page uses three small routes.

**Tech Stack:** Node 20, Express, zod, Prisma/SQLite, vitest (backend); Next.js 14 App Router, no frontend tests.

**Spec:** `docs/superpowers/specs/2026-11-08-settings-design.md` (approved 2026-11-08). Read it first. Out of scope, per the spec: other providers (OpenAI etc.), typed API keys, microphone format changes, non-MP3 spoken formats, speech pricing, per-interviewer models, roles.

## Global Constraints

- Backend commands run from `apps/backend`; single file: `npx vitest run src/__tests__/<file>.test.ts`. Before finishing run backend `npm test` and `npm run build`, frontend `npm run lint` and `npm run build` (from `apps/frontend`).
- Commit steps apply on a feature branch/worktree only, never on `main`; never push.
- Settings are owner-scoped (`ownerOf(res)`; "local" in local mode). New routes sit behind the existing authenticator.
- With an empty settings table the app must behave as it does today when the live list cannot be loaded: built-in fallbacks are `claude-sonnet-4-6` for all three Claude jobs, reply ceiling 300, `scribe_v2`, `eleven_flash_v2_5`, `mp3_44100_128`.
- Recommended defaults are picked once and remembered: when a Claude job has no stored model and the live list loads, resolve the recommendation (replies: newest active `haiku` line; reports and drafts: newest active `sonnet` line; "newest" by `created_at`, "active" by `lifecycle`) and save it; when the list cannot be loaded use the fallback for that call and do NOT save it. A stored value is never changed by a newer model appearing.
- Tiers come from the list's `line` field: `haiku` = Fast, `sonnet` = Balanced, `opus` = Most capable; any other line or null has no tier.
- Spoken-reply formats allowed (exact ids): `mp3_22050_32`, `mp3_24000_48`, `mp3_44100_32`, `mp3_44100_64`, `mp3_44100_96`, `mp3_44100_128` (default), `mp3_44100_192` (page notes it needs ElevenLabs Creator plan or above).
- Reply ceiling range 50 to 1000 (default 300). Speech-to-text id pattern `^[A-Za-z0-9._-]{1,60}$`. Claude and text-to-speech ids must be in the live list or equal the stored value. Price: finite numbers 0 to 100000 per million tokens, `asOf` a valid `YYYY-MM-DD`, at most 50 rows per owner.
- A conversation snapshots its settings when it starts and keeps them; reports and drafts read settings when they run; designer and Try-it sessions use the replies model for conversation and the drafts model for their final draft; a regenerated report uses the reports model current at the time.
- API keys stay in environment variables; no key, header or provider response body in any response, log line or error. Errors carry fixed text and class names only.
- Do not change the 40-word rule, `REPORT_MAX_TOKENS` (3072), `DRAFT_MAX_TOKENS` (6144), the WebSocket protocol, the microphone format (16 kHz mono 16-bit, shown read-only), or the Cartesia fallback.
- Usage records must store the model actually used. Old usage rows keep their computed cost.
- The mock profile needs no keys: mock catalog ids `mock-fast` (line `haiku`), `mock-balanced` (`sonnet`), `mock-capable` (`opus`), TTS `mock-tts-flash`.
- Frontend: keyboard-only usable, visible focus, labels/hints/errors associated, status announced, no horizontal page scroll at 320px, no new animation, WCAG AA with existing tokens.

## Review Focus

Most likely to bite, each pinned by a test in the named task:

1. The Anthropic list fails, is empty, or has an unexpected shape: the page shows current values with the field read-only, no crash, and conversations still run on stored or fallback models (Tasks 2, 4, 6).
2. A fresh install whose list call fails must not break the first conversation, and must not save the fallback as if it were a choice (Tasks 4, 7).
3. A settings change made during a running conversation must not change that conversation (Task 7).
4. An unknown or foreign model id, an unlisted spoken format, or an out-of-range number sent to `PUT` is rejected with a fixed 422 and never reaches a provider (Tasks 4, 6).
5. No API key, request header or provider response text appears in any settings response, log line or error body (Tasks 2, 6).
